# Foldesk 右键服务修复与验收记录

日期：2026-08-31。项目是 **Foldesk 窗口工作台**，不是 FocusDock 或番茄钟。

## 交付范围

本记录原验收安装位置：`/Applications/Foldesk.app`，版本 `1.0.1 (4)`。该版本随后由下方 2026-09-09 的 Build 5 修复取代。本机 macOS 26.5.2（25F84）、Apple Silicon。构建为本机 ad-hoc 签名，不代表已完成对外分发公证。

最终安装可执行文件 SHA-256：`12592d75574b0fc6f93040b39d1feea2f302ba773858e93bf8f2f6dad04cbddd`。

本轮优先修复右键服务及直接影响它的启动、配置、安装问题；不把这些测试等同于整个项目全功能验收。

## 已修复

- 服务冷启动不再初始化窗口工作台；任务结束后退出，不主动显示主窗口。正常打开应用仍显示界面。
- 菜单栏绑定重复回写相同偏好导致的更新循环；缓存应用/品牌图标，避免每次界面刷新重复解码。
- 侧栏切页的共享状态改为在当前界面更新之后发布，消除复测中的更新重入警告。
- NSServices 错误参数从 `NSError **` 修正为要求的 `NSString **`。[Apple 服务实现说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/SysServices/Articles/providing.html)
- 服务上下文原来的 `NSServicesApplicationIdentifier` 错误键修正为 `NSApplicationIdentifier`；选中文件的服务补充文件 URL 和文件类型声明。[Apple 服务属性说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/SysServices/Articles/properties.html)
- 配置损坏/无权读取时停止文件转移和指定 App 打开，不再静默采用默认目标；配置页不再将读取失败后的默认值写回原文件。
- 配置原子保存；保留旧版超过三个槽位的项目并显示为候补，可上移到前三项使用。
- 指定 App 无效时明确报错；三个目录/App 槽位映射一致，并提供排序和可用性提示。
- 缺失 Office 模板时失败，不生成零字节假文档；SwiftPM 测试构建也包含模板。
- 支持以连字符开头的压缩文件名；压缩失败清理未完成产物；混合解压的部分失败不再被成功项掩盖。
- 安装前校验新包，旧安装移到废纸篓可恢复；正常 Run/Verify/Logs 路径统一启动安装版，取消 dist 副本的注册，减少同 Bundle ID 副本争用入口。

## 测试隔离及排除的假失败

- 临时将目录/App 槽位指向测试环境；完成后按原始字节恢复配置。删除动作只针对明确命名的临时测试文件。
- App 返回的 `/private/tmp` 与传入的 `/tmp` 指向同一位置，路径规范化后确认三个 App 实际都成功打开了文件。
- Finder 前台目录/窗口 ID 会变化，初轮新建测试因此出现误判；最终每项建立独立目录窗口验证。误落到其他前台目录的三个测试文档已核对时间、大小和模板内容，移回 `.build/qa-20260831/misdirected-initial-fixtures/`，未删除用户文档。
- 测试产生的访达窗口已按测试目录范围关闭。用户要求停止测试后，已停止采样并将五组临时测试目录及 `.build/qa-20260831/`（含收回的三个测试文档）移到废纸篓，可恢复；隔离接收 App 的注册已取消。项目修复代码、回归测试和本验收记录保留。

## 仍需验证 / 尚未实现

1. **访达真实鼠标右键菜单逐项点击仍需人工验收。** 系统服务执行成功与右键菜单可见性是两层验证；本次自动化选中访达文件不稳定，不能声称全部菜单点击已通过。若菜单没出现，检查系统设置中的服务启用状态。
2. 多显示器切换、不同缩放、长时间驻留、超大文件/压缩包、权限撤销、并发服务等尚未做完整系统级压力验证。
3. 窗口批量关闭、结束工作、分屏/恢复对各第三方 App 的行为没有在用户正在编辑的文档上全量实测，以免影响未保存工作；不能据此称“整个项目全部功能完善”。
4. 配置页已明确标记的“显示/隐藏隐藏文件”“在终端打开目录”仍是未实现计划，不属于本轮已交付服务。

建议下一步先人工验收访达菜单入口，再在隔离工作区进行窗口管理全流程回归。

## 2026-09-09：Build 5 新建文件行为修复

- 用户反馈从访达新建 Office 文件时启动了 WPS。新建成功后原代码仍调用 `activateFileViewerSelecting`；Build 5 已移除新建流程中的所有打开/显示调用，只在当前访达目录写入文件后结束服务。
- 五个菜单项改名为“Foldesk：在此新建 … 文件”，与 WPS 自己的“新建文档”入口区分。
- 12 项右键服务及文件处理相关单元测试通过，Build 5 已后台安装且没有启动 Foldesk 或切换用户窗口。
- 遵守用户要求，本次没有进行会操作访达界面的端到端测试；Build 4 的 20/20 历史验收结果不能替代 Build 5 的人工菜单点击确认。

## 2026-09-10：Build 8 Finder 超级右键

- 原先未参与构建的 Finder Sync 源码已改造成真正以 `_NSExtensionMain` 为入口的 `.appex`，并打包到 `Foldesk.app/Contents/PlugIns/FoldeskFinderSync.appex`；嵌套签名与宿主包校验通过。
- Finder 监听目录不再错误设为 `nil`，改为显式覆盖本机根目录与 `/Volumes`。
- 新建文件统一使用无 UI 的共享核心，支持 11 种类型；创建后不调用 `NSWorkspace.open` 或 `activateFileViewerSelecting`。
- 11 种新建类型也同步到 NSServices 兼容入口，兼容服务由 19 项增至 25 项。
- 新增 7 项创建/扩展打包测试；当前全套 26 项测试通过。验证仅使用系统临时目录并在测试后清理，没有操作用户桌面或 Finder 窗口。
- 扩展包的入口点、Info.plist、沙盒权限、真实 OOXML 模板和嵌套签名已检查。系统插件数据库已接受并启用 `com.foldesk.mac.findersync`，Finder 成功启动扩展进程。真实鼠标点击仍留给用户人工确认；本记录不把进程加载冒充 UI 端到端验收。

## 2026-09-10：Build 10 Finder 动作传递修复

- 实际点击后没有任何创建日志，证明回调在读取请求前已经返回。根因是 Finder 跨进程传递菜单时不会保留自定义 `representedObject`。
- 所有菜单动作改为使用 `NSMenuItem.tag`，请求数据留在扩展实例内部按 tag 查找；新建动作在入口第一行记录日志，不再静默失败。
